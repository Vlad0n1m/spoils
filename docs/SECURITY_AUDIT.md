## Что сделать Владу до продакшена

### Секреты и env

1. `chmod 600 .env .env.idos.local` на VPS и локально: `cp` создаёт файл с правами 644.
2. **Сессии.** `SESSION_SECRET` — 32+ символа (`openssl rand -hex 32`). С более коротким прод не стартует (preflight)
   и не выдаёт сессии. Смена секрета разлогинит всех.
3. **Postgres.**
   - Задать `POSTGRES_PASSWORD`. Переменная действует только при первой инициализации тома.
   - Если том `extract_postgres_data` уже создан со старым паролем, сначала:
     `docker compose exec postgres psql -U postgres -c "alter user postgres password '<новый>'"` (пароль вписать самому),
     потом тот же пароль в `.env` и `docker compose up -d`.
4. **Dev top-up.** `NEXT_PUBLIC_WALLET_DEV_TOPUP=0` (или пусто) и пересобрать web.
   - Для демо-стенда жюри на devnet — осознанно `WALLET_DEV_TOPUP_PRODUCTION=1`.
   - На mainnet пополнение не включится ни при каких флагах.
5. `WORLD_SEED_SECRET` — своё значение. Сейчас он выводится из `GAME_SERVER_HMAC_SECRET`.
6. `OPENAI_API_KEY` не класть в `.env` на VPS: приложению он не нужен.
7. Гостевой режим (`GUEST_PLAY_ENABLED`, `NEXT_PUBLIC_GUEST_PLAY`) в проде — только если он действительно нужен.
8. Новая переменная game server теперь добавляется в `environment:` сервиса в `docker-compose.yml`. Весь `.env`
   он больше не читает.

### nginx

1. Взять обновлённые `deploy/nginx/spoils.conf` и `spoils-idos.conf`, подставить домен, затем `nginx -t && systemctl reload nginx`.
   Новое в образцах:
   - лимиты сокетов и `/matchmake`;
   - `client_max_body_size 16k` на game-хосте;
   - `ssl_protocols`;
   - без Upgrade на web.
2. Если перед доменом будет Cloudflare: раскомментировать `set_real_ip_from` (все актуальные диапазоны с
   cloudflare.com/ips) и `real_ip_header CF-Connecting-IP`. Иначе все игроки делят один лимит логина и регистрации.
3. Не открывать `WEB_BIND/GAME_BIND=0.0.0.0`: это обходит все лимиты nginx.

### Ключи: резервная копия

1. `programs/.keys/` (deploy/authority) — офлайн-копия в менеджере паролей или на зашифрованном носителе. Не в git
   и не в образах: `.dockerignore` и `.gitignore` их уже исключают.
2. `MASTER_SEED_HEX` (из него выводятся все депозитные адреса), `HOT_WALLET_SECRET_B58`, `CHAIN_AUTHORITY_SECRET` —
   зашифрованная копия вне VPS. Потеря `MASTER_SEED_HEX` — потеря доступа ко всем депозитным адресам.
3. `~/Desktop/sol-tokens`:
   - `chmod 600 ~/Desktop/sol-tokens/*.txt` (сейчас 644);
   - лучше перенести ключи с рабочего стола в менеджер паролей или на аппаратный кошелёк.

### Solana CLI: mainnet

1. `solana config set --url devnet --keypair ~/Projects/idosgamessol/programs/.keys/deploy.json` (или любой devnet-ключ).
   Mainnet — только явно: `--url mainnet-beta --keypair ...`. Иначе любая команда `solana` / `spl-token` без
   флагов, в том числе от агента, шлёт реальные транзакции с деплойного ключа.
2. Сменить ключ Alchemy: он был в URL конфига, а `solana config get` печатает его в терминалы и логи.
3. Не запускать `solana config get` в сессиях агентов.

### Платформа (P1)

- Образы на Node 22 и `next` ≥ 15.5.24 до публичного запуска, с полным прогоном тестов на машине посильнее.

## Остаточные риски

- **Сжигание индексов рантайма (P1, №4).** Около 43 аккаунтов, каждый входит до 4 раз за цикл и быстро умирает.
  Лимит регистрации замедляет набор аккаунтов (5 сразу, потом 6 в час с одного IP), но аккаунты живут долго, а IP
  можно менять. Надёжно — переиспользование индексов или допуск на живой шард по уровню, почте или кошельку.
- **Тела сверх вместимости.** После 90 с простоя тело не держит место, поэтому людей на карте может быть больше 24
  (каждый rejoin пускается всегда). Это ограничено только лимитом рантаймов 232; бездействующие тела дешевле
  подключённых. Пул (D17) считается по `poolTargetCount`, не по местам.
- **Лимитеры живут в памяти процесса.** Рестарт web их сбрасывает, несколько инстансов web считают каждый своё.
  Для одного VPS этого достаточно.
- **Без настройки CDN** (`set_real_ip_from`) лимиты auth общие для всех игроков за одним краем CDN.
- **Войд возвращает фунгиблы** (№6) — дубль CR-расходников при войде живого шарда.
- **HMAC** (№8): повтор подписанного запроса в окне 60 с; один ключ на тикеты и на расчёты.
- **Сессии** (№14): украденная кука живёт до 7 дней, отзыва нет.
- **Почта** (№11): регистрация по-прежнему отвечает `email_taken`, только медленнее.
- **Зависимости** (№23–26): Node 20 без патчей, advisories Next 15.5.15 и ws 8.20. В схеме по умолчанию (за nginx)
  они не эксплуатируются.
- **Протокол.** Новые коды закрытия `FLOODED` (4110) и `RESYNC` (4111) клиент показывает как обычный разрыв.
  Честный клиент их не получает.
