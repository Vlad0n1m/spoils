План и состояние отдельной сборки SPOILS для площадки iDos Games и для трека Superteam Kazakhstan ×
iDos Games. Состояние на **05.10.2026**. Пометки: **[проверено]** — видел сам в источнике (MCP-реестр
iDos `@idosgames/mcp`, исходник `@idosgames/core` 0.21.1 на npm, docs.idosgames.com, idosgames.com);
**[не проверено]** — догадка или чужие слова, подтвердить у Ерасыла или на живом тайтле;
**[решает Влад]** — решение владельца, агент его не принимает.

Короткий вывод:

1. Обязательное для трека, по словам Ерасыла: токен игры на Solana, выпущенный через iDos. Сайт
   обещает выпуск токена с bonding curve (без пресейла и доли команды, при капитализации $100K
   ликвидность уходит в DEX, LP сжигаются) **[проверено: текст главной idosgames.com]**. Страница
   `/create-dapp/` рисуется скриптом; шаги, цена и комиссии нигде не описаны **[не проверено]**.
   Выпускает Влад своим кошельком, агент этого сделать не может.
2. iDos хостит только **статичную** сборку на `{titleid}.idos.games` (`begin_build_upload` →
   `finish_build_upload`, право `build:write` у MCP настроек тайтла) **[проверено]**. Наш стек
   (Next.js + Colyseus + Postgres) туда не загружается. Сделано: статичная оболочка
   `deploy/idos-shell` (вход через SDK iDos) + наша игра на своём поддомене в iframe внутри неё.
3. Вход: оболочка входит в iDos (SSO idosgames.com, сохранённая сессия, гость) и передаёт игре
   `UserID` и билет сессии через `postMessage`; наш сервер проверяет билет запросом в Client API iDos
   (`User/GetUsageTime` с `Bearer`-билетом) и только тогда создаёт или открывает аккаунт
   **[механизм проверен по исходнику SDK; привязка билета к UserID — проверить на DEV-тайтле]**.
4. В издании выключена вся SOL-экономика: P2P-рынок и лоты казны, платный стартовый набор, баланс,
   ввод/вывод, dev-пополнение, привязка кошелька, страница `/economy`. Сервер отвечает 404, ссылки и
   кнопки скрыты. Игровой цикл (рейды, лут, CR-торговцы, XP, уровни, пасс, друзья, лидерборды)
   остаётся. Основная сборка без флага ведёт себя как раньше, денежные цифры не тронуты.
5. Задеплоить без Влада нельзя: нужен OAuth MCP настроек тайтла (`/mcp`), тайтл на сайте, VPS с
   доменом и TLS, кошелёк Влада для токена. Пошаговый план — раздел 9, чек-лист сабмита — раздел 10.

## 2. Что известно про iDos (выжимка исследования)

Источники: MCP `@idosgames/mcp` (runtime `@idosgames/core` 0.21.0, `@idosgames/wallet` 0.6.2,
`@idosgames/module-sdk` 0.9.0, `@idosgames/react` 0.4.4, `@idosgames/app-shell` 0.11.0;
скиллы authentication, blockchain-system, cloud-code, currency-system, idosgames-getting-started,
idosgames-title-bootstrap; скелет `get_host_scaffold`), docs.idosgames.com, idosgames.com/mcp/.
Копии лежат в scratchpad сессии (`block-b/idos/`).

### 2.1 Как устроена игра на iDos [проверено]

- Проект = «хост-оболочка» (вход + лобби, `mountHost` из `@idosgames/app-shell`) + модули
  (`src/modules/{id}/`). Игра — модуль с `EngineScene` (Three, Phaser или vanilla canvas).
- Тайтл задаётся в `src/idos.title.ts` (`IDOS_TITLE_ID`, 8 символов `[A-Z0-9]`). У каждого тайтла
  есть DEV-копия `{ID}-DEV`.
- Хостинг: `{titleid}.idos.games` (прод) и `{titleid}-dev.idos.games` (DEV). Сборку загружают
  инструментами MCP настроек тайтла `begin_build_upload` → `finish_build_upload` (Vite, Unity
  WebGL и т. п.), статус смотрят через `get_build`/`list_builds`. Загружается **статичная**
  веб-сборка.
- На idosgames.com игра открывается во фрейме. Внутри фрейма прямой доступ к кошельку из игры
  запрещён (решение iDos от 17.09.2026): `depositToken*`, `withdrawToken*`, `loginWithWallet*`,
  `payWithWalletEvm` возвращают `WALLET_USE_SITE_PANEL`, кнопка кошелька вызывает
  `openPlatformWalletPanel()`, то есть карточку кошелька самого сайта.
- Два MCP: кодовый реестр (`npx -y @idosgames/mcp`, без авторизации, подключён) и MCP настроек
  тайтла (`https://site.idosgames.com/api/v2/mcp`, OAuth 2.1, права `config:read`, `config:write`,
  `cloudcode:write`, `ai:generate`). **Второй не подключён: авторизует только Влад** через `/mcp`.

### 2.2 Вход игроков [проверено]

- `client.auth`: гость (device id), email, Google, Apple, Telegram, кошелёк
  (`requestWalletChallenge` + `loginWithWallet`), SSO-код с idosgames.com (`beginSsoRedirect` →
  `loginWithSsoCode`, работает только на `idosgames.com` и `{id}.idos.games`).
- Во фрейме кошелёк сайта подписывает вход в игру сам (`loginWithWalletViaPlatform`).
- `UserID` в тайтле детерминирован (SHA-256 от email + titleID или device id), у разных способов
  входа разные `UserID`.
- У тайтла есть режим доступа `Blockchain.PlayAccess`: `Open` (по умолчанию), `AnyWithLinkedWallet`,
  `WalletOnly`. Есть гейты по балансу токена. Нам нужен `Open`.
- В комментарии скелета: лимит устройств у тайтла по умолчанию один, новый вход вытесняет живую
  сессию на другом устройстве **[проверено как текст комментария, настройку не видел]**.
- Отдельного серверного API «проверь сессию iDos» в открытых документах нет: страница Server API
  в docs.idosgames.com пустая (04.10.2026) **[проверено]**.

### 2.3 Серверная логика: Cloud Code [проверено]

- Свой JS на серверах iDos (`handlers.*`), игра вызывает `client.cloudCode.execute(name, payload)`.
  В `context.UserID` приходит подтверждённый сервером iDos игрок.
- `server.HttpRequest` ходит наружу только на хосты из allow-list тайтла, только по https, не
  больше 3 запросов за вызов, с лимитом 10 с. Ключи подставляются как `{{secret:NAME}}` и в
  коде не видны.
- Входящие вебхуки: `POST https://api.idosgames.com/api/v2/{titleID}/Public/CloudCode/Webhook/{id}`,
  подпись HMAC-SHA256 в `X-Signature` или токен в `X-Webhook-Token`. Есть расписания (5…10080 мин).
- Публикация скрипта **заменяет всю ревизию**, поэтому сначала читаем текущую.
- Среди `server.*` нет вызова «начислить валюту или предмет». Есть пользовательские данные, данные
  тайтла и квесты. Может ли наш сервер начислять игроку валюту или токен iDos, неясно (вопрос 5).

### 2.4 Валюты, предметы, токен [проверено, кроме выпуска токена]

- Валюты тайтла: виртуальные (целые, `InitialDeposit`, лимиты) и крипто (`CryptoCurrencyDefinition`:
  `Networks[]` с `NetworkID`, `ContractAddress`, `Decimals`, `MinWithdraw`; лимиты вывода в USD,
  KYC-порог; разрешения на ввод, вывод и конвертацию).
- Сети тайтла: `Blockchain.Networks[id]` с `Type: "EVM" | "Solana"`. Для Solana
  `RewardPoolAddress` = Program ID платформы, `VaultDepositAddress` = адрес хранилища для SPL.
- Ввод: игрок сам переводит токен в пул или хранилище, игра сообщает хеш, сервер iDos проверяет и
  зачисляет. Вывод: iDos сразу списывает и выдаёт подпись, игрок отправляет её в сеть. Для вывода
  есть комиссия платформы, минимальный возраст аккаунта (по умолчанию 7 дней), бан за общий адрес
  вывода, дневные и месячные лимиты.
- **Выпуск токена игры:** главная idosgames.com обещает: описываешь игру и токен, подключаешь
  кошелёк, публикуешь; цена идёт по bonding curve; без пресейла и доли команды; при капитализации
  $100K ликвидность переходит на DEX, LP сжигаются; сети BNB Chain и Solana **[проверено как
  маркетинговый текст]**. Сама страница `/create-dapp/` рендерится скриптом, шагов и цен я не
  увидел. В SDK и MCP-реестре инструмента выпуска токена нет **[проверено]**. Выпуск идёт с сайта
  кошельком владельца **[не проверено]**.

### 2.5 Уточнено 05.10.2026

Источники: MCP-реестр (`get_manifest`: `@idosgames/core` 0.21.1, `@idosgames/wallet` 0.6.2,
`@idosgames/module-sdk` 0.10.0, `@idosgames/react` 0.4.4, `@idosgames/app-shell` 0.12.0; скиллы
authentication, blockchain-system, cloud-code, checkout-system, idosgames-getting-started,
idosgames-title-bootstrap, dev-test-loop; `get_host_scaffold`), исходник `@idosgames/core@0.21.1`
(`dist/index.js` с jsdelivr, только чтение), docs.idosgames.com (`llms.txt`, API v2 · User).

**Публикация [проверено].** Право `build:write` у MCP настроек тайтла. Шаги из скилла
idosgames-getting-started: `begin_build_upload { title_id }` → `build_id`, `upload_url` на час,
`asset_base`; собрать статику с `--base=<asset_base>` или `./`; zip содержимого (`index.html` в
корне); `curl -T build.zip "<upload_url>"`; `finish_build_upload { title_id, build_id, deploy }`
→ `TestUrl` (DEV), с `deploy: true` — сразу живая версия; `get_build`, `list_builds`. Использовать
живой id тайтла, не `-DEV`. Пока тайтл не опубликован в дашборде, страницы на idosgames.com нет.
Остальные права MCP: `config:read`, `config:write`, `cloudcode:write`, `ai:generate`,
`kanban:read`, `kanban:write`.

**Свой домен у тайтла [проверено как комментарий в скелете].** Платформа умеет отдавать игру тайтла
на подключённом домене издателя (метка `<meta name="idos-game-host">`), но отдаёт она всё равно
загруженную статику, а не наш сервер. Внешнего адреса игры (URL нашего сервера в настройках тайтла)
в коде и документации нет **[не проверено, вопрос 3]**.

**SSO [проверено по исходнику].** `beginSsoRedirect({ titleID })` уводит на
`https://idosgames.com/sso/?title=…&return_to=…&state=…`; код возвращается во фрагменте URL
(`#idos_sso=…&state=…`), `readSsoCodeFromUrl()` его читает и стирает, `loginWithSsoCode(code)`
меняет на сессию (код живёт 60 с, один обмен, один тайтл). Сервер принимает `return_to` только для
idosgames.com, cloud.idosgames.com, `{id}.idos.games`, `{id}-dev.idos.games` и подключённого домена
тайтла. С нашего поддомена SSO не работает, поэтому вход делает оболочка на `{id}.idos.games`.

**Проверка сессии на нашем сервере [проверено по исходнику и docs API v2].** Клиентский API iDos:
`POST https://api.idosgames.com/api/v2/{TitleID}/Client/{Сервис}/{Действие}/{UserID}`, заголовок
`Authorization: Bearer <ClientSessionTicket>`, тело `{ UserID, ClientSessionTicket, … }`, ответ
`{ Success, Error, Data }`, 401 при плохом или просроченном билете. Наш сервер вызывает
`User/GetUsageTime` (лёгкое чтение, ничего не меняет). Что iDos откажет на билет игрока A в маршруте
игрока B — логично, но не проверено: тест на DEV-тайтле в чек-листе 9.6.

**Экономика iDos [проверено, кроме токена].** Всё, что продаёт тайтл, оценивается `PriceOptions`:
виртуальная валюта тайтла, предметы, крипто-валюта тайтла (баланс в игре, пополняется с кошелька),
покупки Google Play / App Store (`client.purchase`, проверка чеков), реклама, бесплатно. Есть магазин
(`client.store`, витрины, лимиты), лутбоксы, сезоны, лидерборды с наградами, квесты, рефералка
(по умолчанию 5% трат приглашённого в Shop и Marketplace — пригласившему, в виртуальной валюте),
P2P-маркетплейс в валюте тайтла, вывод крипто-валюты с комиссией платформы, минимальным возрастом
аккаунта, KYC-порогом и дневными/месячными лимитами. Внутри фрейма idosgames.com игра не трогает
кошелёк: ввод и вывод — кнопками кошелька сайта. Кто кому платит: игрок платит тайтлу (валюта,
крипто, IAP); платформа берёт комиссию с вывода (процент не опубликован); комиссия платформы с
покупок и с токена (bonding curve, DEX) не опубликована **[не проверено, вопрос 2 и 6]**.

**Документация.** Страницы Server API, Admin API, Secret Key, Platform Settings, Crypto, Integrations
в docs.idosgames.com пустые (05.10) **[проверено]**. Серверного API «начислить валюту игроку» в
открытых источниках нет; Cloud Code тоже не умеет начислять валюту напрямую (`server.*` — данные
игрока и тайтла, квесты `ServerApi`, HTTP наружу).

## 3. План интеграции по шагам

Порядок: сначала то, что не зависит от iDos; потом то, что ждёт ответов.

### 3.1 Флаг сборки и отдельный стек (от iDos не зависит) — сделано

Что уже есть в коде (при выключенном флаге основная сборка ведёт себя как раньше):

1. **Флаг.** `IDOS_BUILD=1` читает `apps/web/next.config.mjs` при сборке и вшивает
   `NEXT_PUBLIC_IDOS_BUILD=1` в клиент и сервер. Поэтому издание — отдельный образ: флаг
   переключается только пересборкой. Логика в `apps/web/src/lib/edition.ts` (и
   `edition-frame.mjs`, его читает next.config), тесты в `edition.test.ts`.
2. **Название.** `BRAND.edition` = «iDos Games edition», `BRAND.fullName` = «SPOILS — iDos Games
   edition» (`apps/web/src/lib/brand.ts`). `BRAND.name` везде остаётся «SPOILS» (логотипы, текст
   подписи кошелька). Полное имя видно в заголовке вкладки и вверху меню аккаунта (☰). В шапку меню
   подпись ещё не выведена: файл `menu-top-bar.tsx` сейчас правит другая задача.
3. **Работа во фрейме.**
   - Заголовок `Content-Security-Policy: frame-ancestors 'self' https://idosgames.com https://www.idosgames.com`
     на всех страницах, только в издании. Список меняется через `IDOS_FRAME_ANCESTORS`
     (https-адреса через пробел или запятую, заменяют список по умолчанию; `*`, `http://` кроме
     localhost, пути и прочий мусор отбрасываются, а если ничего не осталось — берутся адреса по
     умолчанию). `X-Frame-Options` не отправляется ни в одной сборке; в nginx его тоже не добавлять.
   - **Компромисс по `*.idos.games`.** Шаблона `https://*.idos.games` в списке по умолчанию нет: там
     лежат статические сборки всех издателей, и любая чужая игра могла бы встроить наше издание с
     той же partitioned-сессией игрока и подставить кнопки покупки/выставления (clickjacking).
     Цена: если iDos показывает игру через оболочку `https://<titleid>.idos.games` (§3.2), фрейм не
     откроется, пока в `IDOS_FRAME_ANCESTORS` не добавлен точный адрес нашего тайтла, например
     `IDOS_FRAME_ANCESTORS="https://idosgames.com https://www.idosgames.com https://<titleid>.idos.games"`
     (frame-ancestors проверяет всех предков). Шаблон можно вписать только сознательно — сборка
     предупредит об этом.
   - **Защита от CSRF.** Cookie `SameSite=None` уходит и с чужих сайтов, поэтому `src/middleware.ts`
     (`checkApiMutation` в `lib/request-guard.ts`) на каждом изменяющем `/api`-запросе
     (POST/PUT/PATCH/DELETE) отвечает 403 на cross-site / чужой `Origin` и 415 на тела форм
     (`text/plain`, urlencoded, multipart). Запросы самой страницы во фрейме iDos — `same-origin`,
     они проходят. Маршруты игрового сервера (HMAC) и cron (Bearer) проверяются своими ключами.
     Работает в обеих сборках.
   - Cookie сессии в издании: `SameSite=None; Secure; Partitioned` (`lib/session.ts`
     → `editionSessionCookie()`). В основной сборке остаётся `lax`. Partitioned-cookie живёт только
     внутри idosgames.com: если открыть поддомен издания напрямую, вход будет отдельный. Safari может
     резать сторонние cookie и так **[не проверено на устройствах]**, запасной путь — токен сессии в
     заголовке (не сделан).
   - Внутри фрейма (`window.top !== window.self`) пункт «Connect wallet» в меню аккаунта и блок
     привязки кошелька на `/wallet` (выбор кошелька, «Get Phantom») скрыты: во фрейме iDos кошелёк
     ведёт сайт. Вне фрейма (поддомен издания открыт напрямую) они остаются.
   - Pointer Lock и полноэкранный режим во фрейме зависят от атрибутов `allow` у фрейма iDos
     (вопрос 3).
4. **Отдельный стек.** `deploy/idos.compose.yml` — надстройка над `docker-compose.yml`: свой
   compose-проект `spoils-idos` (своя сеть, свои образы, свой том Postgres — значит, своя база),
   свой файл переменных `.env.idos.local`, свои порты (web 3100, игровой сервер 2667),
   `GAME_SERVER_ID` по умолчанию `idos-world-1`. Образ web собирается по тому же
   `apps/web/Dockerfile`, что и основной, с аргументами `IDOS_BUILD` и `IDOS_FRAME_ANCESTORS` (в
   основной сборке они пустые). Nginx: `deploy/nginx/spoils-idos.conf`, `idos.<домен>` → web
   издания, `game-idos.<домен>` → WebSocket.
5. **SOL-экономика выключена** (05.10, см. 3.5): сервер отвечает 404, ссылки и кнопки скрыты.
6. **`IDOS_TITLE_IDS`** (сборка и рантайм): id тайтлов, чья оболочка может входить (`ABCD1234`,
   `ABCD1234-DEV`). Из него при сборке берутся адреса оболочек для моста и, если
   `IDOS_FRAME_ANCESTORS` не задан, для `frame-ancestors` (точные адреса, без шаблонов).

#### Как собрать и запустить издание

На сервере, из корня репозитория:

1. Создать `.env.idos.local` (имя уже в `.gitignore` и `.dockerignore`, в git и в образ не
   попадёт): `cp .env.example .env.idos.local` и заполнить. Секреты **новые**, не копировать из
   основного `.env`: `SESSION_SECRET`, `CRON_SECRET`, `GAME_SERVER_HMAC_SECRET`, `POSTGRES_PASSWORD`,
   `MASTER_SEED_HEX`, `CHAIN_HASH_SALT` и прочие. Обязательно:
   - `IDOS_BUILD=1` (без него команда ниже остановится с ошибкой — защита от запуска с основным `.env`);
   - `NEXT_PUBLIC_GAME_SERVER_URL=wss://game-idos.<домен>`;
   - `GAME_SERVER_ID=idos-world-1` (или любое имя, но не как в основном стеке);
   - `IDOS_TITLE_IDS=<ID>-DEV` (потом `<ID>`): без него мост входа iDos выключен (3.3);
   - `SIWS_ALLOWED_HOSTS` не нужен: привязка кошелька в издании выключена (3.5);
   - `IDOS_FRAME_ANCESTORS` обычно не задавать: без него разрешены idosgames.com,
     www.idosgames.com и точные адреса оболочек из `IDOS_TITLE_IDS`. Если задан — заменяет весь
     список, и адрес оболочки `https://<titleid>.idos.games` надо вписать самому.
   Переменную `DATABASE_URL` compose подставит сам (своя база в контейнере `postgres` проекта).
2. Запуск (нужен Docker Compose 2.24.4+):

   ```bash
   docker compose -p spoils-idos --env-file .env.idos.local \
     -f docker-compose.yml -f deploy/idos.compose.yml up -d --build
   ```

   Все флаги обязательны: `-p` не трогает основной проект `extract` и его том, `--env-file` берёт
   переменные из `.env.idos.local`, а не из `.env`.
3. Nginx: положить `deploy/nginx/spoils-idos.conf`, заменить `SPOILS_DOMAIN`, выпустить сертификат
   (`certbot --nginx -d idos.<домен> -d game-idos.<домен>`). Нужен https: cookie издания `Secure`.
4. Проверка: `curl -sI https://idos.<домен>/play | grep -i content-security-policy` должен показать
   `frame-ancestors 'self' https://idosgames.com https://www.idosgames.com …`. На основном домене
   заголовок другой: только `frame-ancestors 'self'` (аудит безопасности, `src/lib/security-headers.mjs`).
5. После смены `IDOS_BUILD`, `IDOS_FRAME_ANCESTORS` или любого `NEXT_PUBLIC_*` — пересобрать образ
   (тот же `up -d --build`).

Локально без Docker: `IDOS_BUILD=1 pnpm --filter web build` (или `IDOS_BUILD=1` в корневом
`.env` для `next dev`) и отдельная база в `DATABASE_URL`. Для теста фрейма с локальной страницы
добавить её адрес, например `IDOS_FRAME_ANCESTORS="https://idosgames.com http://localhost:5173"`.

### 3.2 Клиент игры на хостинге iDos — сделано 05.10 (`deploy/idos-shell`)

**Требование iDos (Ерасыл, 05.10):** игра хостится у iDos на поддомене тайтла; встраивать чужой сайт
(iframe на наш домен) нельзя. Бэкенд (API, игровой сервер, база) остаётся на нашем VPS.

Поэтому `deploy/idos-shell` — уже не оболочка с iframe, а весь клиент: лобби и PixiJS-клиент из
`apps/web`, собранные Vite в статику (`npm run build`, ~20 МБ, 363 файла).

1. Вход iDos (SSO / сохранённая сессия / гость), как раньше; `autoLogin()` только при сохранённой
   сессии (иначе SDK молча создаёт гостя).
2. Билет iDos → `POST https://idos.<домен>/api/idos/session` → **токен сессии** (та же запечатанная
   iron-session, но в заголовке `Authorization: Bearer`, а не в cookie: на поддомене тайтла это
   стороннее cookie, Safari его режет). Первый вход шлёт `Bearer none`. Токен в localStorage.
3. Все `fetch("/api/…")` приложения уходят на `VITE_SPOILS_API_URL` с токеном (`src/api.ts`);
   игровой сервер — `VITE_SPOILS_GAME_SERVER_URL` (Colyseus сам отвечает CORS).
4. Next-специфичное заменено заглушками: `next/link`, `next/navigation` (`src/shims`); панели лобби
   `/play?panel=…` маппятся на путь страницы (`src/nav.ts`); ссылки на другие страницы сайта
   (новости, правила) открываются на `idos.<домен>` в новой вкладке; шрифты свои (`src/fonts`).
5. Пути к `public/` переписываются в относительные при сборке (тестовая копия живёт в `/v/<build>/`).

Сервер (только `IDOS_BUILD=1`): `lib/session.ts` читает токен из заголовка; CORS и исключение из
CSRF-проверки — только для origin тайтла (`https://<id>.idos.games`, `-dev`) из `IDOS_TITLE_IDS`.

```bash
cd deploy/idos-shell && npm ci
VITE_SPOILS_API_URL=https://idos.spoils.gg VITE_SPOILS_GAME_SERVER_URL=wss://game-idos.spoils.gg \
  VITE_IDOS_TITLE_IDS="8YECHSD4 8YECHSD4-DEV" npm run build
cd dist && zip -qr ../build.zip . -x ".well-known/*" ".gitkeep" && cd ..
```

Проверено 05.10 на тестовой копии (версия 5): гость iDos → мост → аккаунт, лобби с фоном, рейд
через `wss://game-idos.spoils.gg`, стрельба. Подмена `userId` → 401, `/api/me` без токена — без
игрока, чужой origin не получает CORS-заголовков.

### 3.3 Мост входа (auth bridge) — сделано, вариант Б

1. Оболочка (3.2) входит в iDos.
2. Страница издания в iframe (`components/idos/idos-bridge.tsx`, в корневом layout только при
   `IDOS_BUILD=1`) шлёт «hello» каждому разрешённому адресу оболочки (`NEXT_PUBLIC_IDOS_SHELL_ORIGINS`,
   собирается из `IDOS_TITLE_IDS` при сборке) и ждёт ответ только от `window.parent` с этого адреса.
3. Ответ уходит в `POST /api/idos/session` (same-origin, CSRF-проверка middleware). Сервер:
   тайтл должен быть в `IDOS_TITLE_IDS` (рантайм); если сессия уже этого игрока — `same`, без
   запроса в iDos; иначе лимит по IP, проверка билета у iDos (`lib/idos/verify.ts`, таймаут 5 с, при
   сбое iDos — 503, никогда не «пускаем на всякий случай»).
4. Аккаунт: `users.idos_user_id = "{TitleID}/{UserID}"` (unique, миграция 013; DEV и прод — разные
   аккаунты). Первый вход создаёт пользователя: ник из имени iDos по нашим правилам или `raider_NNN`,
   email-заглушка `<sha256>@idos.invalid` (домен `.invalid` не доставляется), пароль не bcrypt — вход
   по паролю в такой аккаунт невозможен. Дальше обычная cookie-сессия издания.
5. Страница перезагружается один раз; при следующих загрузках сервер отвечает `same`.

Билет сессии iDos проходит через наш сервер один раз и нигде не сохраняется. В URL он не попадает.
В основной сборке `/api/idos/*` — 404 (middleware и сам маршрут).

Вариант А (Cloud Code + `server.HttpRequest` на наш хост с `{{secret:…}}`) остаётся запасным, если
iDos не привязывает билет к UserID: тогда меняем `verify.ts` на приём подписанного билета от
обработчика Cloud Code.

### 3.4 Токен игры на Solana через iDos

1. Тайтл: web3, сеть Solana **[решает Влад + ответ iDos: mainnet или devnet]**.
2. Выпуск через idosgames.com → Create (`/create-dapp/`): описание игры и токена, кошелёк Влада,
   публикация. Подписывает Влад; стоимость и комиссии **[решает Влад, не проверено]**.
3. Привязка к тайтлу: `CryptoCurrencies[<id>]` с `Networks[{ NetworkID: "solana", ContractAddress: <mint> }]`
   и `Blockchain.Networks.solana`. Если сайт делает это сам — проверить через `get_currency` /
   `get_blockchain` MCP настроек тайтла **[не проверено]**.
4. Где токен виден: страница и карточка тайтла на idosgames.com, кошелёк сайта (ввод/вывод — только
   там), README и сабмит (адрес mint, ссылка на Solscan).
5. В нашу экономику токен не входит: курсов к CR нет, наград в токене из нашего кода нет (серверного

### 3.5 Экономика издания: что убрано, что остаётся, что заменяет iDos — сделано

Основание: на iDos деньги ходят через тайтл (его валюты, магазин, крипто-валюта = токен игры, кошелёк
сайта), а не через P2P-торговлю за SOL с нашим кастодиальным балансом; во фрейме сайта игра к
кошельку не допускается. Поэтому в издании вся SOL-часть выключена **на сервере** (404) и **в UI**
(скрыто). Переключатель один: `IDOS_BUILD=1` → `lib/edition.ts` (`SOL_ECONOMY`, `EDITION_UI`,
`editionBlock`). Основная сборка не меняется; денежные цифры не тронуты.

| Наше (основная версия) | В издании | Как |
|---|---|---|
| P2P-рынок за SOL, лоты казны (первичные продажи) | **убрано** | `/api/market/*` → 404; вкладка Shop · Market исчезает (Shop = только Traders, старые ссылки `tab=market` ведут к Traders); кнопка «Sell on market» и окно выставления скрыты |
| Платный стартовый набор (SOL) | **убрано**; без набора игрок идёт в рейд с базовым снаряжением (как сейчас у всех без набора) | `/api/stash/starter` → 404; карточка набора и «Buy starter kit» скрыты. Набор за CR или за валюту тайтла iDos — **[решает Влад]** (новая цена = новая денежная цифра) |
| Баланс SOL, ввод, вывод, dev-пополнение | **убрано** | `/api/wallet/*`, `/api/withdraw` → 404; плашка баланса и «Wallet» в складе скрыты; `/wallet` → редирект на `/play` |

| Рейды, лут, потерянный пул, XP, уровни, пасс, квесты, друзья, пати, лидерборды | остаётся | без изменений |
| Вход | аккаунт iDos через мост (3.3); свой логин/пароль и гость — запасной при прямом открытии | `/api/idos/session` |
| Токен игры (SPL через iDos) | крипто-валюта тайтла; ввод/вывод кошельком сайта | вне нашего кода (3.4) |
| Награды за лидерборды и сезоны | в нашей игре только косметика, как и раньше; призы в валюте/токене — конфигом лидербордов iDos | **[решает Влад]**, после ответа iDos о начислениях |

Тексты без SOL: правила (Info · Rules: блок «Credits» вместо «Two currencies»), Shop · Traders
(«Credits stay in the game…»), подсказка Shop, гейт склада, пустой склад, лендинг, меню аккаунта
(«iDos Games account» вместо email-заглушки), aria-метка дока. Дочищено 05.10: страница `/alpha` и
строки альфы на лендинге, в регистрации и в Info (`content/alpha.ts`: «No real money…» вместо тестового
рыночного баланса, без набора, кошелька и ссылки на Economy), патч-ноуты (`content/news.ts`: без блока
Sign-In with Solana, «Valuables go back into the loot pool» вместо казны), правила Info («valuables go
back to the lost pool»), ссылки «Economy» на `/news` и в правилах, пустой лоадаут («Buy gear from the
traders» вместо «Buy a starter kit»), множитель хламщика в чеке рейда («junker ×» вместо «market ×»).

Предметы казны в издании. В основной версии в казну (`items.state = 'treasury'`) уходят: налог 1%
с входящей в потерянный пул стоимости (`enterPool` → `applyTreasuryTax`) и уники, исчезнувшие с
трупом игрока или с земли (A6, `expireToTreasury`); казна потом продаёт их на рынке. В издании рынка
нет, и такие предметы копились бы навсегда, поэтому (`lib/economy/pool.ts`, параметр `treasury`,
по умолчанию `SOL_ECONOMY`):
- налог 1% не берётся: всё, что входит в пул, остаётся в потерянном пуле, аккумулятор `tax_acc` не
  трогается;
- A6-истечение кладёт уники обратно в потерянный пул (`lost_pool`, без износа, без налога, причина
  `expire`); привязанные (bound) и изношенные (0 %) уничтожаются — так же, как по правилам пула;
  в итоге `raids/end` они считаются в `pooled`, `treasury` = 0;
- демо-сид (`scripts/seed-economy.ts`) в издании по умолчанию не создаёт лотов казны (`--listings=0`).
Основная сборка не меняется. Тесты: `lib/inventory/raids.test.ts` («iDos edition (no treasury)…»).

`/api/stash` в издании не отдаёт `balance`, `market` и `kit` (поля опущены, не нули; лишние запросы не
делаются); клиент считает их необязательными (`hasStashMoney`, `lib/lobby/stash-response.ts`).
Награда уровня «Market selling unlocked» в издании не показывается нигде (`defaultSellUnlockLevel` →
null: таблица наград, вкладка Rewards, окно повышения уровня, Info).

Оставшиеся хвосты:
- cron `chain-events` (события на Solana devnet от нашего ключа) в издании не трогал: без
  `CHAIN_AUTHORITY_SECRET` он сам отвечает `configured:false`.

### 9.2 Сервер, DNS, TLS (Влад, агент подскажет)

1. VPS (тот же, что основной, если тянет; см. `SCALING.md`), Docker Compose 2.24.4+, nginx, certbot.
2. DNS: `A`-записи `idos.<домен>` и `game-idos.<домен>` → IP VPS.
3. На VPS из корня репозитория: `cp .env.example .env.idos.local`, заполнить **новыми** секретами
   (не копировать основные): `SESSION_SECRET`, `CRON_SECRET` (16+ символов), `GAME_SERVER_HMAC_SECRET`,
   `WORLD_SEED_SECRET`, `POSTGRES_PASSWORD`, `MASTER_SEED_HEX` (64+ hex; без него `/api/idos/session` не
   создаст аккаунт), `CHAIN_HASH_SALT`. Генерация, например: `openssl rand -hex 32`. Обязательно:
   - `IDOS_BUILD=1`
   - `IDOS_TITLE_IDS=<ID>-DEV` (на время теста), потом `<ID>` или `"<ID> <ID>-DEV"`
   - `NEXT_PUBLIC_GAME_SERVER_URL=wss://game-idos.<домен>`
   - `GAME_SERVER_ID=idos-world-1`
   - `NEXT_PUBLIC_SITE_URL=https://idos.<домен>`
   - `IDOS_FRAME_ANCESTORS` — не задавать (тогда: idosgames.com, www.idosgames.com и адреса
     оболочек из `IDOS_TITLE_IDS`); задавать только если iDos покажет игру с другого адреса
   - `SIWS_ALLOWED_HOSTS` не нужен (привязка кошелька в издании выключена)
4. Запуск:

   ```bash
   docker compose -p spoils-idos --env-file .env.idos.local \
     -f docker-compose.yml -f deploy/idos.compose.yml up -d --build
   ```

   Проверка конфигурации без запуска: тот же набор флагов с `config` вместо `up -d --build`
   (05.10 агент прогнал с заглушками: проект `spoils-idos`, порты 3100/2667 на 127.0.0.1, свой том
   `spoils-idos_postgres_data`, `IDOS_TITLE_IDS` доходит до сборки web).
5. nginx: `deploy/nginx/spoils-idos.conf` → заменить `SPOILS_DOMAIN`, `nginx -t && systemctl reload nginx`,
   `certbot --nginx -d idos.<домен> -d game-idos.<домен>`.
6. Проверки:

   ```bash
   curl -sI https://idos.<домен>/play | grep -i content-security-policy
   #   frame-ancestors 'self' https://idosgames.com https://www.idosgames.com https://<id>-dev.idos.games
   curl -s -o /dev/null -w '%{http_code}\n' https://idos.<домен>/api/market/listings   # 404

   ```

7. После смены `IDOS_BUILD`, `IDOS_TITLE_IDS`, `IDOS_FRAME_ANCESTORS` или любого `NEXT_PUBLIC_*` —
   пересобрать образ тем же `up -d --build`.
