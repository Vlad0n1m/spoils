План отдельной сборки SPOILS для площадки iDos Games и для трека Superteam Kazakhstan × iDos Games.
Состояние на 04.10.2026. Пометки: **[проверено]** — видел сам в источнике (MCP-реестр iDos
`@idosgames/mcp`, docs.idosgames.com, idosgames.com); **[не проверено]** — догадка или слова с чужих

Короткий вывод:

1. Обязательное для трека, по словам Ерасыла: токен игры на Solana, выпущенный через iDos. Сайт
   iDos прямо обещает выпуск токена игры на Solana с bonding curve **[проверено: текст главной
   idosgames.com]**, но как это сделать и сколько стоит, в документации нет. Это главный вопрос к
   Ерасылу.
2. Наш стек (Next.js, Colyseus, Postgres) не загружается в iDos как статичная сборка. Рабочая

   токен iDos в цены не встраиваем.
4. Без ответов Ерасыла по вопросам 1–5 (раздел 5) начать интеграцию нельзя. Сейчас это блокер.

## 1. Что такое iDos-издание

| | Основная версия | iDos-издание |
|---|---|---|
| Код | монорепо `idosgamessol` | тот же код, флаг сборки `IDOS_BUILD=1` |
| Название в интерфейсе | SPOILS | «SPOILS — iDos Games edition» (`BRAND.name` не меняем, добавляем подпись издания) |
| Где открывается | свой домен, Android TWA | в iframe на idosgames.com (через оболочку на `{titleid}.idos.games`) |
| Вход | логин/пароль, гость, SIWS-кошелёк | аккаунт iDos (SSO idosgames.com, кошелёк через сайт), наш сервер получает подтверждённый `UserID` iDos |
| База | своя Postgres | **отдельная** Postgres, отдельный стек web + game-server + cron |
| Поддомен | `SPOILS_DOMAIN`, `game.SPOILS_DOMAIN` | например `idos.SPOILS_DOMAIN` и `game-idos.SPOILS_DOMAIN` **[решает Влад]** |
| Связь с основной версией | — | **нет**: аккаунты, склад, баланс, рынок не общие |
| Деньги | как в `GAME_DESIGN.md` | те же цифры; какие денежные функции включены, решает Влад (см. 3.5) |

Зачем отдельно: в чужом iframe действуют чужие правила (кошелёк только через сайт iDos, своя
политика cookie), а держать два режима входа и две экономики в одной базе рискованно. Отдельная
база значит, что ошибка в мосте iDos не тронет игроков основной версии.

## 2. Что известно про iDos (выжимка исследования)

Источники: MCP `@idosgames/mcp` (runtime `@idosgames/core` 0.21.0, `@idosgames/wallet` 0.6.2,
`@idosgames/module-sdk` 0.9.0, `@idosgames/react` 0.4.4, `@idosgames/app-shell` 0.11.0;
скиллы authentication, blockchain-system, cloud-code, currency-system, idosgames-getting-started,
idosgames-title-bootstrap; скелет `get_host_scaffold`), docs.idosgames.com, idosgames.com/mcp/.
Копии лежат в scratchpad сессии (`block-b/idos/`).

### 2.1 Как устроена игра на iDos [проверено]

- Проект = «хост-оболочка» (вход + лобби, `mountHost` из `@idosgames/app-shell`) + модули
  (`src/modules/{id}/`). Игра — модуль с `EngineScene` (Three, Phaser или vanilla canvas).
- Тайтл задаётся в `src/idos.title.ts` (`IDOS_TITLE_ID`, 8 символов `[A-Z0-9]`). У каждого тайтла
  есть DEV-копия `{ID}-DEV`.
- Хостинг: `{titleid}.idos.games` (прод) и `{titleid}-dev.idos.games` (DEV). Сборку загружают
  инструментами MCP настроек тайтла `begin_build_upload` → `finish_build_upload` (Vite, Unity
  WebGL и т. п.), статус смотрят через `get_build`/`list_builds`. Загружается **статичная**
  веб-сборка.
- На idosgames.com игра открывается во фрейме. Внутри фрейма прямой доступ к кошельку из игры
  запрещён (решение iDos от 17.09.2026): `depositToken*`, `withdrawToken*`, `loginWithWallet*`,
  `payWithWalletEvm` возвращают `WALLET_USE_SITE_PANEL`, кнопка кошелька вызывает
  `openPlatformWalletPanel()`, то есть карточку кошелька самого сайта.
- Два MCP: кодовый реестр (`npx -y @idosgames/mcp`, без авторизации, подключён) и MCP настроек
  тайтла (`https://site.idosgames.com/api/v2/mcp`, OAuth 2.1, права `config:read`, `config:write`,
  `cloudcode:write`, `ai:generate`). **Второй не подключён: авторизует только Влад** через `/mcp`.

### 2.2 Вход игроков [проверено]

- `client.auth`: гость (device id), email, Google, Apple, Telegram, кошелёк
  (`requestWalletChallenge` + `loginWithWallet`), SSO-код с idosgames.com (`beginSsoRedirect` →
  `loginWithSsoCode`, работает только на `idosgames.com` и `{id}.idos.games`).
- Во фрейме кошелёк сайта подписывает вход в игру сам (`loginWithWalletViaPlatform`).
- `UserID` в тайтле детерминирован (SHA-256 от email + titleID или device id), у разных способов
  входа разные `UserID`.
- У тайтла есть режим доступа `Blockchain.PlayAccess`: `Open` (по умолчанию), `AnyWithLinkedWallet`,
  `WalletOnly`. Есть гейты по балансу токена. Нам нужен `Open`.
- В комментарии скелета: лимит устройств у тайтла по умолчанию один, новый вход вытесняет живую
  сессию на другом устройстве **[проверено как текст комментария, настройку не видел]**.
- Отдельного серверного API «проверь сессию iDos» в открытых документах нет: страница Server API
  в docs.idosgames.com пустая (04.10.2026) **[проверено]**.

### 2.3 Серверная логика: Cloud Code [проверено]

- Свой JS на серверах iDos (`handlers.*`), игра вызывает `client.cloudCode.execute(name, payload)`.
  В `context.UserID` приходит подтверждённый сервером iDos игрок.
- `server.HttpRequest` ходит наружу только на хосты из allow-list тайтла, только по https, не
  больше 3 запросов за вызов, с лимитом 10 с. Ключи подставляются как `{{secret:NAME}}` и в
  коде не видны.
- Входящие вебхуки: `POST https://api.idosgames.com/api/v2/{titleID}/Public/CloudCode/Webhook/{id}`,
  подпись HMAC-SHA256 в `X-Signature` или токен в `X-Webhook-Token`. Есть расписания (5…10080 мин).
- Публикация скрипта **заменяет всю ревизию**, поэтому сначала читаем текущую.
- Среди `server.*` нет вызова «начислить валюту или предмет». Есть пользовательские данные, данные
  тайтла и квесты. Может ли наш сервер начислять игроку валюту или токен iDos, неясно (вопрос 5).

### 2.4 Валюты, предметы, токен [проверено, кроме выпуска токена]

- Валюты тайтла: виртуальные (целые, `InitialDeposit`, лимиты) и крипто (`CryptoCurrencyDefinition`:
  `Networks[]` с `NetworkID`, `ContractAddress`, `Decimals`, `MinWithdraw`; лимиты вывода в USD,
  KYC-порог; разрешения на ввод, вывод и конвертацию).
- Сети тайтла: `Blockchain.Networks[id]` с `Type: "EVM" | "Solana"`. Для Solana
  `RewardPoolAddress` = Program ID платформы, `VaultDepositAddress` = адрес хранилища для SPL.
- Ввод: игрок сам переводит токен в пул или хранилище, игра сообщает хеш, сервер iDos проверяет и
  зачисляет. Вывод: iDos сразу списывает и выдаёт подпись, игрок отправляет её в сеть. Для вывода
  есть комиссия платформы, минимальный возраст аккаунта (по умолчанию 7 дней), бан за общий адрес
  вывода, дневные и месячные лимиты.
- **Выпуск токена игры:** главная idosgames.com обещает: описываешь игру и токен, подключаешь
  кошелёк, публикуешь; цена идёт по bonding curve; без пресейла и доли команды; при капитализации
  $100K ликвидность переходит на DEX, LP сжигаются; сети BNB Chain и Solana **[проверено как
  маркетинговый текст]**. Сама страница `/create-dapp/` рендерится скриптом, шагов и цен я не
  увидел. В SDK и MCP-реестре инструмента выпуска токена нет **[проверено]**. Выпуск идёт с сайта
  кошельком владельца **[не проверено]**.

## 3. План интеграции по шагам

Порядок: сначала то, что не зависит от iDos; потом то, что ждёт ответов.

### 3.1 Флаг сборки и отдельный стек (от iDos не зависит) — сделано

Что уже есть в коде (при выключенном флаге основная сборка ведёт себя как раньше):

1. **Флаг.** `IDOS_BUILD=1` читает `apps/web/next.config.mjs` при сборке и вшивает
   `NEXT_PUBLIC_IDOS_BUILD=1` в клиент и сервер. Поэтому издание — отдельный образ: флаг
   переключается только пересборкой. Логика в `apps/web/src/lib/edition.ts` (и
   `edition-frame.mjs`, его читает next.config), тесты в `edition.test.ts`.
2. **Название.** `BRAND.edition` = «iDos Games edition», `BRAND.fullName` = «SPOILS — iDos Games
   edition» (`apps/web/src/lib/brand.ts`). `BRAND.name` везде остаётся «SPOILS» (логотипы, текст
   подписи кошелька). Полное имя видно в заголовке вкладки и вверху меню аккаунта (☰). В шапку меню
   подпись ещё не выведена: файл `menu-top-bar.tsx` сейчас правит другая задача.
3. **Работа во фрейме.**
   - Заголовок `Content-Security-Policy: frame-ancestors 'self' https://idosgames.com https://www.idosgames.com`
     на всех страницах, только в издании. Список меняется через `IDOS_FRAME_ANCESTORS`
     (https-адреса через пробел или запятую, заменяют список по умолчанию; `*`, `http://` кроме
     localhost, пути и прочий мусор отбрасываются, а если ничего не осталось — берутся адреса по
     умолчанию). `X-Frame-Options` не отправляется ни в одной сборке; в nginx его тоже не добавлять.
   - **Компромисс по `*.idos.games`.** Шаблона `https://*.idos.games` в списке по умолчанию нет: там
     лежат статические сборки всех издателей, и любая чужая игра могла бы встроить наше издание с
     той же partitioned-сессией игрока и подставить кнопки покупки/выставления (clickjacking).
     Цена: если iDos показывает игру через оболочку `https://<titleid>.idos.games` (§3.2), фрейм не
     откроется, пока в `IDOS_FRAME_ANCESTORS` не добавлен точный адрес нашего тайтла, например
     `IDOS_FRAME_ANCESTORS="https://idosgames.com https://www.idosgames.com https://<titleid>.idos.games"`
     (frame-ancestors проверяет всех предков). Шаблон можно вписать только сознательно — сборка
     предупредит об этом.
   - **Защита от CSRF.** Cookie `SameSite=None` уходит и с чужих сайтов, поэтому `src/middleware.ts`
     (`checkApiMutation` в `lib/request-guard.ts`) на каждом изменяющем `/api`-запросе
     (POST/PUT/PATCH/DELETE) отвечает 403 на cross-site / чужой `Origin` и 415 на тела форм
     (`text/plain`, urlencoded, multipart). Запросы самой страницы во фрейме iDos — `same-origin`,
     они проходят. Маршруты игрового сервера (HMAC) и cron (Bearer) проверяются своими ключами.
     Работает в обеих сборках.
   - Cookie сессии в издании: `SameSite=None; Secure; Partitioned` (`lib/session.ts`
     → `editionSessionCookie()`). В основной сборке остаётся `lax`. Partitioned-cookie живёт только
     внутри idosgames.com: если открыть поддомен издания напрямую, вход будет отдельный. Safari может
     резать сторонние cookie и так **[не проверено на устройствах]**, запасной путь — токен сессии в
     заголовке (не сделан).
   - Внутри фрейма (`window.top !== window.self`) пункт «Connect wallet» в меню аккаунта и блок
     привязки кошелька на `/wallet` (выбор кошелька, «Get Phantom») скрыты: во фрейме iDos кошелёк
     ведёт сайт. Вне фрейма (поддомен издания открыт напрямую) они остаются.
   - Pointer Lock и полноэкранный режим во фрейме зависят от атрибутов `allow` у фрейма iDos
     (вопрос 3).
4. **Отдельный стек.** `deploy/idos.compose.yml` — надстройка над `docker-compose.yml`: свой
   compose-проект `spoils-idos` (своя сеть, свои образы, свой том Postgres — значит, своя база),
   свой файл переменных `.env.idos.local`, свои порты (web 3100, игровой сервер 2667),
   `GAME_SERVER_ID` по умолчанию `idos-world-1`. Образ web собирается по тому же
   `apps/web/Dockerfile`, что и основной, с аргументами `IDOS_BUILD` и `IDOS_FRAME_ANCESTORS` (в
   основной сборке они пустые). Nginx: `deploy/nginx/spoils-idos.conf`, `idos.<домен>` → web
   издания, `game-idos.<домен>` → WebSocket.
5. **Ещё не сделано:** ссылки на `/wallet` (меню аккаунта, валюта, магазин, склад) и сама страница
   с балансом и выводом SOL во фрейме остаются. Скрывать ли вывод SOL, **[решает Влад]**.

#### Как собрать и запустить издание

На сервере, из корня репозитория:

1. Создать `.env.idos.local` (имя уже в `.gitignore` и `.dockerignore`, в git и в образ не
   попадёт): `cp .env.example .env.idos.local` и заполнить. Секреты **новые**, не копировать из
   основного `.env`: `SESSION_SECRET`, `CRON_SECRET`, `GAME_SERVER_HMAC_SECRET`, `POSTGRES_PASSWORD`,
   `MASTER_SEED_HEX`, `CHAIN_HASH_SALT` и прочие. Обязательно:
   - `IDOS_BUILD=1` (без него команда ниже остановится с ошибкой — защита от запуска с основным `.env`);
   - `NEXT_PUBLIC_GAME_SERVER_URL=wss://game-idos.<домен>`;
   - `GAME_SERVER_ID=idos-world-1` (или любое имя, но не как в основном стеке);
   - `IDOS_FRAME_ANCESTORS`, как только известен адрес тайтла: полный список, например
     `https://idosgames.com https://www.idosgames.com https://<titleid>.idos.games` (без него игра
     откроется только во фрейме прямо на idosgames.com, не внутри оболочки тайтла).
   Переменную `DATABASE_URL` compose подставит сам (своя база в контейнере `postgres` проекта).
2. Запуск (нужен Docker Compose 2.24.4+):

   ```bash
   docker compose -p spoils-idos --env-file .env.idos.local \
     -f docker-compose.yml -f deploy/idos.compose.yml up -d --build
   ```

   Все флаги обязательны: `-p` не трогает основной проект `extract` и его том, `--env-file` берёт
   переменные из `.env.idos.local`, а не из `.env`.
3. Nginx: положить `deploy/nginx/spoils-idos.conf`, заменить `SPOILS_DOMAIN`, выпустить сертификат
   (`certbot --nginx -d idos.<домен> -d game-idos.<домен>`). Нужен https: cookie издания `Secure`.
4. Проверка: `curl -sI https://idos.<домен>/play | grep -i content-security-policy` должен показать
   `frame-ancestors 'self' https://idosgames.com https://www.idosgames.com …`. На основном домене этого
   заголовка нет.
5. После смены `IDOS_BUILD`, `IDOS_FRAME_ANCESTORS` или любого `NEXT_PUBLIC_*` — пересобрать образ
   (тот же `up -d --build`).

Локально без Docker: `IDOS_BUILD=1 pnpm --filter web build` (или `IDOS_BUILD=1` в корневом
`.env` для `next dev`) и отдельная база в `DATABASE_URL`. Для теста фрейма с локальной страницы
добавить её адрес, например `IDOS_FRAME_ANCESTORS="https://idosgames.com http://localhost:5173"`.

### 3.2 Оболочка на хостинге iDos

Если iDos разрешит указать внешний адрес игры (вопрос 3), оболочка не нужна: тайтл открывает
`idos.<домен>` напрямую, вход см. 3.3, вариант Б.

Иначе:

1. Новый пакет `apps/idos-shell` (Vite): скелет `get_host_scaffold`, базовые модули
   (`profile`, `inventory`, `invite`, `friends`, `quests`, `mailbox`) и свой модуль `spoils-frame`.
2. `spoils-frame` — «Play»-модуль: во весь экран iframe на `https://idos.<домен>/play#t=<билет>`
   (билет из 3.3), `allow="fullscreen; autoplay; gamepad"`. Шапку лобби (баланс, кошелёк сайта)
   оставляем, iDos её рисует сам.
3. `IDOS_TITLE_ID` прописывает Влад, когда будет тайтл. Сборку загружает агент через MCP
   настроек тайтла (`begin_build_upload`/`finish_build_upload`), но только после OAuth-авторизации
   Влада. Сначала DEV-тайтл, потом прод.
4. Риск: вложенный фрейм (idosgames.com → `{id}.idos.games` → наш домен). Работает ли так
   ввод, звук, полноэкранный режим и cookie на телефоне, проверять на живом тайтле.

Третий путь — переписать клиент PixiJS в модуль iDos (`EngineScene` vanilla) и ходить к нашему
API с чужого origin. Тогда меню, склад и рынок (страницы Next.js) пришлось бы переносить. До 13.10
это нереально, не предлагаю.

### 3.3 Мост входа (auth bridge)

Вариант А, через Cloud Code [механизм проверен, настройка ждёт iDos или Влада]:

1. Игрок входит в оболочку способом iDos (SSO сайта, кошелёк сайта, email).
2. Оболочка вызывает `client.cloudCode.execute("spoilsTicket")`.
3. Обработчик на iDos: `server.HttpRequest` POST на `https://idos.<домен>/api/idos/bridge` с
   заголовком `Authorization: Bearer {{secret:SPOILS_BRIDGE_SECRET}}` и телом
   `{ userId: context.UserID, titleId, ts }`.
4. Наш сервер сравнивает секрет постоянным временем, находит или создаёт пользователя
   (`users.idos_user_id`, unique) и отдаёт одноразовый билет на 60 с.
5. Обработчик возвращает билет в игру. Оболочка открывает iframe с билетом во фрагменте URL
   (фрагмент не попадает в логи сервера). Наша страница меняет билет на сессию через
   `POST /api/idos/exchange` и стирает фрагмент.

Что для этого нужно на стороне iDos: наш хост в allow-list тайтла, секрет `SPOILS_BRIDGE_SECRET` в
Integrations (вписывает Влад, в репозиторий не кладём), право `cloudcode:write` для публикации
скрипта.

Вариант Б: iDos даёт серверный API проверки сессии или подписанный токен игрока (вопрос 4). Тогда
оболочка передаёт `clientSessionTicket`, а наш сервер проверяет его у iDos. Если есть, этот путь
проще.

В обоих вариантах наш сервер **не доверяет** ничему, что пришло из браузера без подписи iDos или
нашего билета.

### 3.4 Токен игры на Solana через iDos

1. Тайтл: web3, сеть Solana **[решает Влад + ответ iDos: mainnet или devnet]**.
2. Выпуск токена через idosgames.com (create-dapp): название, тикер, картинка, кошелёк Влада.
   Подписывает Влад, агент кошелёк не трогает. Стоимость и комиссии **[решает Влад]**.
3. Привязка к тайтлу: `CryptoCurrencies[<id>]` с `Networks[{ NetworkID: "solana", ContractAddress: <mint> }]`
   и `Blockchain.Networks.solana` (Program ID пула платформы). Если сайт делает это сам, только
   проверяем через `get_blockchain`/`get_currency` **[не проверено]**.
4. Где токен виден игроку: в лобби оболочки (полоса валют и кошелёк сайта рисуются базой), в README
   и на странице сабмита (адрес mint, ссылка на эксплорер).
5. Ввод и вывод токена идут кнопками кошелька сайта iDos. В наш код вывод токена не встраиваем.

### 3.5 Валюта и предметы: что маппим, что остаётся нашим

Денежные цифры (цены в SOL, комиссии, размер раздачи, курсы) не меняем и в iDos не дублируем.

| Наше | В iDos-издании | Почему |
|---|---|---|
| CR (мягкая валюта, не выводится) | остаётся в нашей базе издания, в iDos не зеркалим | CR никогда не конвертируется в деньги; зеркало в iDos открыло бы такой путь через их конвертацию |
| SOL-рынок P2P, первичные продажи | как в основной версии, отдельная база. Включать ли во фрейме, **[решает Влад]**; варианты: выключить (демо-правила `ECONOMY_DEMO_RULES=1`, `ECONOMY_MODE=demo`) или оставить | во фрейме iDos кошелёк только через сайт, а наш рынок завязан на свой кошелёк |
| Предметы, склад, лут | только наши (сервер — источник истины) | инвентарь iDos (`client.item`) не знает наших правил рейда |
| Токен iDos (SPL на Solana) | крипто-валюта тайтла iDos; в нашу экономику не входит, курса к CR и SOL нет | требование трека без вмешательства в наши цифры |
| Возможные награды в токене (сезон, лидерборд) | только если iDos даст серверное начисление (вопрос 5) или выплата пойдёт вручную с кошелька Влада; размер **[решает Влад]** | — |
| Бейдж держателя токена (косметика, без силы) | опционально: обработчик Cloud Code передаёт в билете признак баланса (`server.ReadUserData(["InventoryV2"])`) **[не проверено, что раздел доступен]** | Solana-использование токена в игре без денег в механике |
